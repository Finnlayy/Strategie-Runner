# Kraken Strategy Runner - Agent Rules

## Python Execution Environment
* When spawning or executing Python scripts from Node.js (e.g., via `child_process`), **ALWAYS** use the project's virtual environment executable (`.venv/bin/python`) instead of the global `python` or `python3` binary. This ensures all heavy data-layer dependencies (Polars, DuckDB, FastAPI) are correctly loaded.
* Do not use `python3 -c` for multi-line scripts if it can be avoided, as it can cause syntax errors. If necessary, ensure it is fully encapsulated in a script file or properly quoted.

## DuckDB & Parquet Data Lake
* **Timezone Dependency:** When using DuckDB to query Parquet files generated by Polars (which often contain `Datetime("ns", "UTC")`), DuckDB relies on the `pytz` library under the hood. You must ensure `pytz` is installed in the Python environment, otherwise DuckDB queries (like `min(timestamp)`) will crash with a `ModuleNotFoundError`.
* **Glob Corruption:** DuckDB's `read_parquet('path/*/*.parquet', union_by_name=true)` will fail entirely if a single parquet file in the glob is corrupted (e.g. `TProtocolException`). If queries fail mysteriously, check for corrupt files and move them out of the lake directory.
